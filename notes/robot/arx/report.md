## 1. 结论与推荐方案

**用两条完整Seeed B601-DM构建桌面双臂系统，在轻载遥操作、数据采集和抓放任务上具备可行性。它需要作为新平台完成机械集成、标定和控制适配。** 相似外观、六轴结构或同系列电机不足以证明它与现有ACOne等效。

首版建议：两条完整DM及夹爪；按用户约束采用600×140×85mm整体底座，J1轴距500mm、J2轴高146.5mm；取消原独立底板并设计内部安装结构及固定头部相机架；左右独立CAN与动力保护；使用现有Ubuntu主机。先完成低速单臂、双臂独立控制与标定，再做交接、共同持物和学习策略。原ACOne保留作任务基准。

本地已保存13个仓库相关文件快照，共2,610个文件、557,672,275字节；4个方舟7z包已解压，共80个文件；63个STEP/STP已逐个读入分析，41个上游URDF已解析。下载范围是本任务相关目录/类型，不是13个仓库完整Git历史。以上为第一阶段基线；随后LIFT补充新增290个文件、两款整机模型及控制/手册资源，见[LIFT横向比较](topics/12_lift_resources_and_comparison.md)。电机确认已按[用户实机与本地代码证据（工作区资料）](sources.md#artifact-a135e3561bde)更新。每个来源有提交、原始地址与SHA256，见[来源清单（工作区资料）](sources.md#artifact-0fc163fa7eda)、[机器清单（工作区资料）](sources.md#artifact-ccc9513d6ea6)。

## 2. 逐项回答

| 问题 | 目前结论 | 新平台要做什么 |
|---|---|---|
| 官方STEP和其他格式是否下载 | 已下载ACOne body、head_camera、A5平台等STEP；A5/X5/ACOne包内为URDF/STL/CSV等，没有发现完整单臂STEP | 用实体参考底座/头架，用URDF与网格分析机械臂 |
| 最大臂展如何比较 | Seeed官方767mm；旧ARX5官方620mm不能直接当当前ACOne同TCP规格。共同腕中心+150mm虚拟TCP时，ACOne/X5约753.1mm、DM约760.9mm（数值候选） | 见[臂展定义与完整对比](topics/14_arm_reach_comparison.md)，不将其当作实机有效工作区 |
| link长度相同吗 | 部分相同，整体不同；DM与X5上臂均264mm，小臂和腕不同；A5差别更大 | 建立新FK/IK和惯量模型 |
| 构型相同吗 | 相近6R串联结构，但坐标、转轴方向、限位、腕部和工具不相同 | 新建整机模型、关节映射与TCP |
| 电机模组相同吗 | 用户已实机确认ACOne前三轴EC_A4310，后三轴及夹爪DM_J4310；Seeed前三轴DM4340P，后三及夹爪DM4310 | 核对实物型号、固件、减速器和参数 |
| 肩宽、底座能一样吗 | R2采用500mm J1轴距，底座600×140×85mm、J2高146.5mm，与公开ACOne模型对齐 | 取消原DM独立底板，内部承力/布线尚需验证 |
| 头部相机怎么定 | 原URDF无独立光学frame；按任务覆盖、遮挡、像素尺度与相机模式确定 | 支架可调，重新标定内外参 |
| 基座高度怎么定 | 先定义桌面、安装面和肩轴，再扫描任务IK、碰撞和载荷 | 不把frame高度差直接当加工垫块厚度 |
| 回零一样吗 | 没有相同证据；电机零点、URDF零位、安全home、遥操作校准是不同概念 | 左右分别标定，备份原机配置 |
| 电源、MCU、转换器一样吗 | 常见24V供电，但功率、线序、桥接驱动和内部MCU未证明相同 | 首版用现成配套供电/CAN，无需先复刻MCU |
| CAN/485、协议一样吗 | DM从臂为CAN；主臂UART、桥接串口与RS485不能混称；MIT形式相似不保证ID/量化相同 | 从桥接、帧、厂家模式、单位到SDK逐层适配 |
| 原ACOne数据可迁移吗 | 任务框架可适配，轨迹需原FK→任务坐标→新IK；策略需重新评估 | 不直接重放原始关节轨迹 |
| 异常失能后如何防坠 | 大Kd/重力补偿只在驱动可控时有效；内部保护或失电后需要独立机械承托/制动 | 先捕获与日志，核对首个错误码、24V及失能调用；见[防坠专题](topics/15_fall_prevention_and_emergency_stop.md) |
| 急停如何避免砸桌 | 健康驱动受控减速→闸/支撑承重→动力隔离；失控/失电由独立捕获覆盖 | 两路NC、硬件安全逻辑、制动与最终切断、手动复位；储能不得旁路急停 |

## 3. 机械长度与安装

按相邻转轴直线的最短距离比较，单位mm。此定义避免将沿转轴移动原点误当成link变化，不是壳体长度或joint xyz向量模长。

| 相邻轴 | A5 | X5-2025 | Seeed DM |
|---|---:|---:|---:|
| J1–J2 | 20.000 | 20.000 | 20.084 |
| J2–J3 | 218.403 | 264.000 | 264.000 |
| J3–J4 | 189.000 | 251.319 | 248.537 |
| J4–J5 | 77.000 | 67.750 | 78.308 |
| J5–J6 | 0 | 0 | 0 |

零位根坐标轴方向：X5约[+Z,+Y,−Y,−Y,−Z,+X]，DM约[+Z,−Y,+Y,+Y,−Z,+X]。轴方向差首先可能是坐标约定，不代表必须购买镜像机械臂；结合几何、零位和限位才能构建映射。

DM的J2距其base原点140.2mm，X5为100.5mm，A5为113mm。A5底部网格约z=−9.25mm，若它就是实际支撑面，肩轴相对该面约122.25mm，与DM差17.95mm；不能只拿frame差27.2mm去加工。完整ACOne根坐标也未证明是桌面。[机械报告](topics/02_mechanical_comparison.md)记录原始关节坐标、旋转、限位、质量、支撑面差和孔位候选。

ACOne body约600×162.207×379.695mm；head_camera约76×88.607×294.695mm，后三个实体已包含在body中，不应重复装配。源STEP坐标与URDF不同，本轮未求得光学外参。DM原底板140×200×14mm，识别到64×64mm连接孔阵列，但未确认是对外台面安装孔，不直接据此下单。

Seeed两个整机STEP中，20260425含389实体且整体拓扑检查未通过；20260625含367实体且检查通过。两者姿态/坐标/组件不同，包围盒不是臂展。前版保留对照，见[拓扑审计（工作区资料）](sources.md#artifact-9d02b500c4ca)；拓扑问题不能直接解释为真机结构故障。

## 4. 已建立可调双臂概念模型

![双DM概念平台](assets/previews/bi_seeed_concept.png)

[概念URDF（工作区资料）](sources.md#artifact-e8fea1e1d71b)已更新为R2：整体底座600×140×85mm、J1轴距500mm、J2距底部支撑面146.5mm。DM base坐标高6.3mm，不是底座厚度或直接可加工的垫板尺寸。原单臂底板从派生可视/碰撞网格移除，J1主体位于底座内，输出/承力座穿出顶盖；原关节几何保留。新增[底座原生STEP（工作区资料）](sources.md#artifact-2d2f6ad8c3b6)及[R2详细设计与边界](topics/11_acone_aligned_base_r2.md)。相机仍高750mm、俯角60°，没有声称与ACOne光学位置相同。尺寸/FK和静态代理检查已通过，结构、全运动碰撞、持续负载和制造验证尚未完成。

相机应按最终任务区和RGB/深度模式选位置。例如D435 RGB约69°×42°，垂直观察要覆盖1.0×0.6m矩形，距离需约0.782m再留余量；斜视需投影任务区角点及物体高度，不能直接套垂直公式。相机越高覆盖越大，小物体像素越少。具体扫描、结构和标定步骤见[布局与相机设计](topics/05_layout_and_camera_design.md)。

## 5. 控制接入前必须处理的源码差异

本轮固定源码静态检查发现以下事项，详见[控制报告](topics/04_protocol_and_control.md)。上游原文件保持原样，未进行真机故障测试。

1. LeRobot普通DM关节调用`send_pos_vel(pos_rad, 32)`，忽略从配置换算出的速度变量；该接口单位为rad/s。应在自有适配层改为经过限幅、单位明确的速度，并核对发送帧。
2. Seeed SDK前三轴MIT的Kd配置为8，本轮MotorBridge编码上限为5；若组合走该路径会限幅。需固定实际依赖与控制模式，不能以YAML当发送值。
3. SDK包元数据要求Python>=3.10,<3.12，教程使用3.12。CAD分析环境不等于已验证机器人控制环境。
4. URDF与LeRobot的关节限位/方向不同；电机、模型、策略三层映射分别保存。
5. 单臂7电机、每周期一命令一反馈、每帧约130bit、1Mbps时，500Hz理论占用约91%；两臂共线约182%。建议首版两条独立总线100–250Hz起步，实测控制抖动、反馈年龄和相机时间偏移。
6. 防坠专项静态审计确认：SDK的`estop()`直接`disable_all()`；重力补偿启动存在失能后等待0.1秒再使能的窗口；无反馈state会补零，退出/配置也有失能路径。这些不能作为悬空承重安全停车。实际用户安装版本尚待确认，不能将静态发现当成已定位的事故根因。

## 6. 热、电气与成本

Seeed V4公开测试中，1.5kg满伸展静态保持约3分钟过热，70%伸展约18分钟，较小范围动态工况表现更好。持续负载必须带姿态、工作半径、任务周期和温度条件，不能只说“可拿1.5kg”。先用轻载、靠近躯干的任务建立基线。[电机与电气报告](topics/03_motors_and_electrical.md)记录逐关节型号、ID、额定/峰值区别、温升、供电、MCU与接口。

首版两路动力保护、左右独立CAN、明确接地/线序、故障停机与断电支撑。24V、Type-C、XT30或同厂家芯片不能单独证明兼容；内部MCU型号未知也不阻止采用配套桥接板开发。

用户已报告DM异常下使能后砸桌，因此防坠是进入双臂运行前的必要工作包。新增[防坠与急停专题](topics/15_fall_prevention_and_emergency_stop.md)，包含9处固定代码证据、机械承托/断电闸、Kd作用边界、24V储能/回生计算、硬件急停框图、宇树与ALOHA官方实例和12项待实测验收。以24V降至20V为说明性假设，10000μF在150W下理想只维持约5.87ms；不能把大电容当最终防坠措施。当前R2概念CAD尚未集成实体抱闸或防坠立架。

公开BOM电机列价合计1005USD/臂、2010USD/两臂，仅为BOM参考算术，不是完整套件当前售价。待报价预算见[project_bom.csv（工作区资料）](sources.md#artifact-fe9d409f9a7b)，套件已含项目不重复计价。材料、加工、相机、线束、运输、返工、工程及维护时间都应计入；目前不足以计算相对ACOne节省百分比。

## 7. 机械、硬件、控制与算法如何展开

机械层：定义任务和安装基准，扫描肩宽/高度/yaw，做任务位姿IK与整机碰撞，核实真实孔位，再完成框架、相机架、布线CAD、载荷/紧固件检查和加工装配图。

硬件层：核对出货电机/固件/桥接版本、线序与供电，完成单臂台架，设计左右保护、急停、接地和线缆；在完整采图和日志负载下测USB/CAN。

控制层：统一坐标和单位，左右分别标定零位/限位/TCP，双设备绑定、共同时间轴、反馈年龄、轨迹插值、共享碰撞场景和故障状态机。之后再评估重力补偿、柔顺和共同持物。

算法层：单臂抓放→双臂分工→交接→扶持→共同持物，形成带版本的数据与标定，再评估ACT/DP或VLA。按相同任务的成功率、失败类别、连续运行和成本对照原ACOne。

完整阶段、退出条件和验收见[实施路线P0–P8](topics/06_build_and_validation_plan.md)。记录模板包括[关节标定（工作区资料）](sources.md#artifact-91922c5496cb)、[台架测试（工作区资料）](sources.md#artifact-3bdae16b9e04)、[相机标定（工作区资料）](sources.md#artifact-9393a91847b8)。
